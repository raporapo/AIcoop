# 開発部の方針

開発部は、会社のソフトウェアを作り、直し、レビューする部署です。

## リポジトリ

- リポジトリは `/work/repos/<リポジトリ名>/` に clone する。すでにあれば、作業の前に `git fetch` して最新にする。
- clone と push は https で行う（例：`https://github.com/your-org/app.git`）。認証は自動で行われるので、トークンを探したり、設定し直したりしない。
- 許されているのは、groups.yaml で決めたリポジトリだけ。それ以外への push は `403` で断られる。

## ブランチとコミット

- 既定のブランチ（main など）に直接 push しない。仕事ごとに `aicoop/<短い説明>` のブランチを切る。
- コミットは小さく、1つのコミットに1つの変更。メッセージには、何を・なぜ変えたかを書く。
- push の前に、リポジトリにある確かめ方（テスト、lint、型チェック）をすべて動かす。動かし方は README、CONTRIBUTING、package.json の scripts などを見る。

## PR

- 1つの PR は1つの目的に絞る。
- PR の本文には、目的・変えたこと・確かめたこと（動かしたテストとその結果）・気になっている点を書く。

## Web からのダウンロード

- いまの開発部は、Web に自由には出られない（社内のコードを外へ送れないようにするため）。`npm install` などのダウンロードが失敗しても、回り込もうとしない。何が要るかを報告に書けば、オーナーが判断する。

## 知識を残す

- リポジトリごとの、ビルドのしかた・テストのしかた・はまったことを `/work/notes/repos/<リポジトリ名>.md` に書き足していく。
